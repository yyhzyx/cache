Skill（技能）

概念学习资料 · 由 concept-learner 生成并人工核查

一、个人解释

Skill 是一套「可复用、可沉淀的任务知识与流程」的封装——本质是一个目录加一个 SKILL.md 文件。它通过「渐进式披露」按需加载到 Agent 的上下文里，让一个通用 Agent 变成某个领域的专家，而不需要每次都重新写一遍 prompt。

换个说法：Skill 就像给新员工写好的「上岗手册」，把「该做什么、按什么步骤做、注意什么」固化下来，谁接手都能照着用。

二、核心机制 / 组成

  • 目录结构：SKILL.md（必需）+ scripts/（可选脚本）+ references/（按需加载的文档）+ assets/（模板资源）。
  • YAML frontmatter：最关键是 name 和 description，Agent 启动时会把所有已安装 Skill 的名字和描述预加载进系统提示。
  • 渐进式披露（Progressive Disclosure）：三层加载——第一层元数据（常驻）→ 第二层 SKILL.md 正文（相关时才读）→ 第三层引用文件（需要时才读）。
  • 与上下文的关系：因为只在需要时加载，Skill 能在「不挤爆上下文」的前提下，给 Agent 提供近乎无限的领域知识。

三、一个具体应用场景

场景：用本仓库的 concept-learner 学习一个新概念。

  1. 用户说「帮我用 concept-learner 学习『微调（Fine-tuning）』」。
  2. Agent 从系统提示里看到 concept-learner 的名字和描述，判断它适合这个任务。
  3. Agent 读取完整的 SKILL.md，按其中的「生成步骤」产出：个人解释、核心机制、应用场景、辨析、自测题、来源。
  4. 产出后按「自检要求」逐项核对，再交付给用户。

同一个 Skill 可以反复用于任何概念，这就是「可复用」的价值。

四、容易混淆的问题 / 使用边界

容易混淆澄清
Skill ≠ PromptPrompt 是一次性的文本；Skill 是结构化、可复用、可组合、按需加载的「流程 + 知识」包。
Skill ≠ 工具/API工具是「能执行的动作」；Skill 主要提供「流程知识」，虽然它也能附带脚本。
Skill ≠ 模型微调Skill 不改变模型权重，只是往上下文里注入指令和知识。

使用边界

  • 不适合放「一次性任务」；适合沉淀「会反复用到的流程/规范」。
  • SKILL.md 建议保持精炼，过长的细节应拆到 references/，靠渐进式披露按需加载。
  • 描述（description）要写清「做什么 + 何时用」，否则 Agent 无法在合适时机触发它。
