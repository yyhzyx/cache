Agent（智能体）

概念学习资料 · 由 concept-learner 生成并人工核查

一、个人解释

Agent 是「一个会自己干活、会用工具的 LLM」。普通的 LLM 只会「一问一答」，而 Agent 会在一个大循环里：理解目标 → 规划步骤 → 调用工具 → 观察结果 → 再决定下一步，直到任务完成。它把模型的「脑子」和外部世界的「手脚」连了起来。

一个更朴素的比喻：普通聊天机器人像「只动嘴的顾问」，而 Agent 像「能自己动手完成交付的助手」——它不只告诉你该怎么做，还会真正去查资料、写代码、调用 API，把结果做出来。

二、核心机制 / 组成

一个典型 Agent 通常由以下几部分拼装而成：

  • 模型（LLM）：作为「大脑」，负责理解、推理与决策。
  • 工具（Tools）：搜索、代码执行、文件读写、调用外部 API 等，是 Agent 与真实世界交互的「手脚」。
  • 记忆（Memory）：短期记忆靠「上下文」，长期记忆靠外部存储（数据库、向量库）。
  • 规划（Planning）：把大任务拆成可执行的子步骤。
  • 环境反馈循环（Loop）：观察 → 行动 → 再观察，这是 Agent 区别于单次调用的关键。

一个经典的实现范式是 ReAct（Reasoning + Acting）：模型交替进行「推理（想）」和「行动（做）」，边想边做。

三、一个具体应用场景

场景：AI 编程助手（如 Claude Code、Cursor）修复一个 Bug。

  1. 用户说「这个登录接口偶发 500 错误，帮我查一下」。
  2. Agent 先理解目标，规划：先看日志 → 定位代码 → 提出修复。
  3. 它调用工具：读日志文件、搜索相关代码、查看最近的提交。
  4. 根据工具返回的结果，它判断可能是某个空指针问题，于是修改代码并运行测试。
  5. 测试通过后，它总结修改原因；若失败，则回到上一步继续排查。

整个过程里，Agent 不是一次性回答，而是「边做边看结果边调整」，这就是环境反馈循环的体现。

四、容易混淆的问题 / 使用边界

容易混淆澄清
Agent ≠ 带工具的 LLM 单次调用Agent 的关键在于「循环 + 自主决策」，不是简单地把工具结果塞回一次回答里。
Agent vs Workflow（工作流）Workflow 是「预先写死路径」的编排（代码决定步骤）；Agent 是「LLM 运行时动态决定下一步」。Anthropic 建议能用简单方案就别上 Agent。
Agent ≠ 一定要全自动很多好的 Agent 会在关键节点「停下来问人」，全自动只是程度问题，不是必要条件。

使用边界（什么时候不该用 Agent）

  • 任务路径可预测、可写死时，用 Workflow 更可控、更便宜。
  • 任务一次调用就能完成时，直接用 LLM 单次调用即可。
  • 错误代价高且不可恢复时，需要加沙箱、护栏和人工检查点。
  • Agent 往往更慢、更贵、还可能累积错误，复杂度应是「最后手段」而非起点。
